# 產品總覽（Overview）

## 問題陳述（Problem Statement）

公司現行 ICSOP（Instruction / Control / Standard Operating Procedure）文件管理方式分散，缺乏統一的瀏覽入口、身分追溯與流程結構化管理。本平台建立單一系統，讓公司同仁可透過 RWD 網頁瀏覽/搜尋/下載/列印 ICSOP 文件（含身分浮水印與稽核追蹤），並讓管理者以「循環（Life Cycle）」DAG 工作流程結構維護文件、帳號、權限與組織同步。

## 目標使用者（Target Users）

| 角色 | 說明 | 主要需求 |
|------|------|----------|
| 一般使用者（User） | 公司同仁 | 前台瀏覽/搜尋/篩選/下載/列印文件 |
| ICSOP 管理員（ICSOPAdmin） | 文件與循環維護者 | 循環 DAG、ICSOP 文件全生命週期、使用表單 |
| 系統管理員（SysAdmin） | 平台管理者 | 帳號/角色管理、組織同步操作、系統參數 |
| 主管（Supervisor） | 當責室長/部門主管 | 前台瀏覽（唯讀）、ICSOP 文件與全公司循環唯讀查看（無調閱歷程／使用表單管理權） |
| 部門窗口（DeptContact） | 部門聯絡窗口 | 前台瀏覽（對文件管理唯讀） |

> 系統上下文與外部整合：見 [system-architecture.mmd](diagrams/system-architecture.mmd)。

## 目標（Goals）

1. 提供統一、可追溯（浮水印＋稽核）的 ICSOP 文件瀏覽與取得管道。
2. 以循環 DAG（有向無環）結構化管理文件於工作流程中的歸屬。
3. 與上游系統整合完成身分驗證與組織/人員/職級每日同步。
4. 以角色×功能、角色×欄位雙層權限矩陣落實存取控管。

## 非目標（Non-Goals）

- 不含本地 LLM 之**微調/訓練**（智慧問答（E09 F027–F035）定案採 RAG，非微調）、預測分析、文件內容智慧分類、異常調閱偵測。
- 不保留 ICSOP 文件歷史版本檔（僅保存當前版本，覆蓋儲存）。
- 不對文件狀態切換設簽核流程（管理員手動切換）。
- 不回寫上游系統（組織來源為唯讀）。
- 不由本平台新增/刪除角色種類（5 種固定）。

## 成功指標（Success Metrics，皆可量測）

| 指標 | 目標 |
|------|------|
| 兩種登入方式核發有效 session 且未授權請求一律被拒 | 100% 未授權請求被拒 |
| 5 種角色登入後導向正確畫面 | 100% 正確 |
| 閒置 30 分鐘後下一次操作被導回登入頁 | 100%（操作中不被登出） |
| 每日組織同步可追溯（成功/失敗、異動筆數） | 每次執行皆產生 1 筆 SYNC_RUN |
| DAG 資料庫中不存在成環的邊 | 0 成環邊 |
| 文件編號重複無法儲存 | 0 重複編號 |
| 查看/下載/列印各產生獨立稽核紀錄且與浮水印一致 | 100% 一致；稽核不可竄改 |
| 前台三斷點核心功能可操作 | 桌機/平板/手機皆通過 |

## 交付分期（僅代表優先序，非功能取捨）

- **Phase 1**：核心登入/分流/帳號、組織同步與離職停用、循環 DAG（含唯讀樹狀圖預覽 F036）、ICSOP 文件 CRUD、使用表單、前台瀏覽/浮水印/稽核（含調閱歷程與變更歷程 F037/F038）、權限矩陣。
- **Phase 2**：F006 組織異動主動通知強化（US-013）、F022 後台開新視窗開啟前台頁（US-056）。
- **Phase 1（E09 管理端 ingestion）**：F027–F031 .xls 原件保存/PDF 產出、模板感知抽取清洗、章/節 chunking＋metadata＋向量索引、改版重抽/舊版排除、管理端索引可視性（為 Phase 3 準備乾淨、有 metadata 的知識庫）。
- **Phase 3（E09 前台智慧問答）**：F032–F035 本地開源 LLM＋RAG 之自然語言問答（附引用來源、權限感知檢索、防幻覺護欄、問答稽核＋經 AI 導引之浮水印/稽核）。

詳見 [scope.md](scope.md)。E09 智慧問答技術路線與分期依據專案根目錄 `AI-RAG-評估報告.md` 定案。
