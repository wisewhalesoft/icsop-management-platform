# F006: 組織異動影響提示與異動管理後台
Priority: P1 | Status: Draft | Last Updated: 2026-07-20
Epic/Story: E02 / US-013（Phase 2）, US-014（Phase 1）

> 合併理由：異動提示（US-013）與整合後台頁（US-014）為同一管理情境；提示清單即後台頁主要內容之一。Phase 1 先以後台清單呈現，Phase 2 強化主動通知。

## Description
當組織/人員/職級異動可能影響某文件的制定公司/制定部門/制定室別、當責室長（主要/次要）、使用部門時，系統於受影響文件產生「組織異動待確認」提示（非強制、不自動覆寫）。後台整合頁呈現同步狀態總覽、同步歷史、待確認提示清單，並可直接導向對應文件之制定組織/當責室長設定編輯。

## Preconditions
- F004 同步已產生異動紀錄；F014 制定組織/當責室長欄位已存在關聯人員/部門。

## Main Flow
### 提示產生（US-013）
1. 同步偵測人員部門/職級異動（非離職）或組織單位異動。
2. 比對其是否為某文件之當責室長-主要/次要，或原部門/組織單位為文件之制定公司/制定部門/制定室別/使用部門。
3. 於受影響文件產生 `ORG_CHANGE_ALERT`（列出受影響具體欄位、異動前後差異），狀態 `pending`。

### 提示情境：在職者掛於已關閉部門（契約 §7.3）
3a. 同步後偵測「`EMPSTS='A'` 之在職者，其 `DEPTID` 對應部門之 `CLOSE_DATE` 已過（即 `CLOSE_DATE <= GETDATE()`，非哨兵 `9999-12-31`）」。
3b. 為該批人員產生「組織異動待確認」提示，列出人員、其所掛已關閉部門代碼／名稱、部門關閉日期。
3c. **不停用帳號、不自動改派部門**，交由管理員人工確認後處理。實測 AS 共 **11 人**屬此情境。

### 後台頁（US-014）
4. 同步狀態總覽：最近一次同步時間、觸發方式、結果、異動筆數，含「立即同步」按鈕（F004）。
5. 同步歷史頁籤：分頁列出過去執行紀錄，失敗可展開錯誤訊息。
6. 待確認異動頁籤：列出 `pending` 提示，點擊直接導向對應文件制定組織/當責室長設定（F014）。

### 提示處理
7. 管理員更新欄位或標記「已確認無需變更」→ 提示狀態 `resolved`，記錄處理者/時間。

## Alternative Flows
- Phase 2：主動通知（站內/Email，管道待確認 OQ-E02-03a）。

## Edge Cases
- 一人為多份文件當責室長：其異動觸發多筆獨立提示，各自可處理。
- 人員異動與該文件當責欄位無關聯：不誤判產生不相關提示。
- **在職者掛於已關閉部門**：產生待確認提示，**帳號維持啟用**（不觸發 F005 停用）；同一人於後續同步仍處此狀態時，不重複產生新提示（維持既有 `pending` 一筆）。
- 掛已關閉部門之在職者同時為某文件當責室長：兩類提示各自獨立產生，可分別處理。

## Postconditions
- 受影響文件被看見（不靜默忽略）；文件狀態與既有制定組織/當責室長設定維持不變直到人工處理。

## Acceptance Criteria
- Given 當責室長轉調, When 同步後, Then 對應文件出現「組織異動待確認」並標示「當責室長-主要」受影響。
- Given 文件之制定部門/制定室別對應組織單位異動, When 同步後, Then 對應文件出現「組織異動待確認」並標示受影響之制定組織欄位。
- Given 文件被標示待確認, When 管理員尚未處理, Then 文件狀態與制定組織/當責室長設定不被自動覆寫。
- Given 管理員更新欄位或標記無需變更, When 處理完成, Then 提示自清單移除並記錄處理者/時間。
- Given 進入後台頁, When 載入, Then 顯示最近同步時間/方式/結果/異動筆數與「立即同步」。
- Given 點擊待確認項目, When 導向, Then 正確帶入該文件 ID 至制定組織/當責室長設定編輯畫面。
- Given 非授權角色, When 存取本頁 API, Then 回 403。
- Given 某在職者（`EMPSTS='A'`）所屬部門之 `CLOSE_DATE` 已過, When 同步完成, Then 待確認清單出現該人員之「掛於已關閉部門」提示，含部門代碼／名稱與關閉日期。
- Given 在職者掛於已關閉部門, When 同步完成, Then 其帳號維持啟用狀態，不被 F005 停用。
- Given 同一在職者於連續兩次同步皆掛於已關閉部門且提示尚未處理, When 第二次同步完成, Then 不產生重複提示。

## Error Scenarios
- 權限不足：見 [error-handling.md#permission](../error-handling.md#permission)。
- 提示是否需比文件狀態切換更嚴謹之處理流程：未定案（OQ-E02-03b）。
