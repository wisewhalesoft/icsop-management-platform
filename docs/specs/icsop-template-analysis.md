## 1. 全 corpus 規模（收斂 OQ-NFR001 文件數量級）

主索引 `手冊目錄` 之 `總目錄catalogue` 工作表實列 **633 列**，其中「文件編號」欄非空 **≈ 598 筆** → **ICSOP 程序書總量約 598 份**，與先前估計「約 600 份、約 1 萬 chunk」**吻合**。

索引每列欄位：循環作業編號（如 `HFC-SRC-101`）、**文件編號**（如 `ICSOP-SRC-101-1`）、細項編號（`-00`/`-01`…）、Title 標題、內容摘要、（撰寫）權責部門（主／次）、階段（一/二/三）、月份、小計。

- 文件編號格式 `ICSOP-<循環代碼>-<階層>-<細項>` **與 [OQ-E04-03](open-questions.md) 定案之編號慣例一致**。
- 「權責部門」值（企劃部／審查部／資金部／營管部…）為**真實組織單位**，與 [upstream-hr-source-contract.md](upstream-hr-source-contract.md) 盤點之組織階層一致（交叉驗證通過）。
- 主索引另有 01～09 分類子表與「推進時程」「ISO 對應」等 38 個工作表——屬導入管理用，非程序書內容。

## 2. 標準模板結構（確認）

真實樣本程序書為 **5 個工作表**，與 spec 假設之「標準五表」**完全一致**：

| 工作表 | 角色 | 樣本規模 |
|---|---|---|
| `封面` | 文件 metadata ＋ 簽核區 | 50 列 |
| `目錄&目的` | 章節目錄 ＋ 目的／適用範圍／連結點 | 90 列 |
| `.流程圖` | 作業流程圖（繪圖物件） | 83 列 |
| `作業流程` | **主體內容**（章／節／執行者／作業內容） | 399 列 |
| `變更履歷` | 版次變更記錄表 | 271 列 |

> **關鍵發現：模板一致性旗標**。每個工作表右側（O/P/Q 欄一帶）皆有 **「標準格式」** 字樣標記。此為**機器可偵測的模板一致性訊號**——全 corpus 變體率盤點時，可先以此旗標＋工作表名稱集合（是否恰為上述五表）自動分類，大幅降低人工判讀成本（見 §5）。

## 3. 各工作表解剖（F028 抽取依據）

### 3.1 重複頁首（每表皆須剝除）
每個工作表第 0–2 列皆重複一段頁首區塊：文件標題、`文件編號：ICSOP-…`、`制定部門：…`、`版次：YY'NN`、`頁次：N of M`、`制定日期：…`。
→ **F028 須剝除此重複頁首**（符合「丟棄頁首頁尾」），但其中的**文件編號／版次／制定部門可作為 metadata 抽取來源**（供 F029 掛 chunk metadata）。

### 3.2 `封面`
標題、文件編號、制定部門、版次、頁次、制定日期，以及**簽核區**（當責室長＋部門主管＋簽署欄）。
→ **簽核區含人員姓名，F028 須丟棄**（符合「丟棄簽核區」）。

### 3.3 `目錄&目的`
結構化章節目錄，樣本之標準章節骨架為：
目的 → 適用範圍 → 連結點程序書 → **第1章 作業流程圖** → **第2章 作業流程說明**（含第1~N節）→ 第3章 定期自檢及異常管理 → 第4章 使用表單 → 第5章 附錄 → 文件變更履歷。
→ 此章節骨架可作為 **F029 章／節切 chunk 的結構錨點**。

### 3.4 `作業流程`（主體，RAG 內容來源）
以 **章／節** 分段（`第X章`／`第X節`），每節下有標籤化欄位：**執行者**、**作業時限**、**作業內容**。
→ **直接驗證 F029「依章／節切 chunk」設計可行**；執行者/作業時限為天然的 chunk metadata。

### 3.5 `變更履歷`
表格：版次／生效日期／變更項次／變更內容簡述。
→ 對應 [F037 文件變更歷程](features/F037-document-change-history.md)之來源語意（惟本系統變更歷程以 DB 記錄為權威，此表為文件內嵌版）。

### 3.6 `.流程圖`
以繪圖物件（shapes）呈現流程圖，儲存格文字稀疏。
→ **本輪 RAG 不抽取流程圖影像內容**（OQ-E09-05 定案不含 OCR）；僅 `作業流程` 之文字為檢索來源。

## 4. 對 F028／F029 的結論

1. **標準模板之抽取管線設計可行**——樣本結構與 F028/F029 假設吻合：五表、章/節結構、可剝除的重複頁首、可丟棄的簽核區。
2. **抽取目標明確**：內容 chunk 來源 = `作業流程` 工作表之章/節文字；metadata 來源 = 頁首（文件編號/版次/制定部門）＋主索引（循環/使用部門/階段）。
3. **章/節切分有現成錨點**：`目錄&目的` 的章節骨架 ＋ `作業流程` 的 `第X章`/`第X節` 標記。

## 5. 仍未收斂：全 corpus 變體率（OQ-E09-04 之核心）

**本分析僅有 1 份真實樣本**，無法測定 598 份中有多少偏離標準五表（歷史遺留版型、非標準章節、跨欄合併異常等）。此為 OQ-E09-04 之核心問題，**仍 `[BLOCKING]`**，須待可存取檔案 corpus 後盤點。

**建議的低成本盤點法**（供實作/PoC 階段執行）：
1. **旗標掃描**：對全 corpus 之 .xls 逐檔檢查 (a) 工作表名稱集合是否恰為 `封面/目錄&目的/*流程圖/作業流程/變更履歷`；(b) 是否含「標準格式」標記。二者皆符 → 標準；否則列為變體候選。此步驟純結構、可全自動、不需人工。
2. **分層抽樣人工複核**：對變體候選，依主索引之類別（01～09）與年份分層抽樣，人工確認實際版型差異類型與數量。
3. 以旗標掃描之「非標準比例」作為 F028 涵蓋率風險的量化指標，回填 OQ-E09-04 與 [nfr.md#rag-quality](nfr.md#rag-quality) AC5（索引建置吞吐）之風險評估。

> 取得 corpus 的前置：ICSOP .xls 原件目前不在本專案；需上游提供檔案存取（比照 [upstream-hr-source-contract.md §11](upstream-hr-source-contract.md) 之上游交付項）。
