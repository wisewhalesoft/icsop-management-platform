## 矩陣來源逐格對照

### F025 角色×功能（權威＝F025 spec 表格；中文權限值 → 列舉）

對映規則：`CRUD→'CRUD'`、`唯讀／全部唯讀→'READ'`、`無→'NONE'`。

**表達決策（非 spec 衝突，特此註記）**：spec 中「前台瀏覽」「下載/列印文件」兩列之值為「可」／「可（浮水印）」——係普遍可存取列（五角色一致、無寫入型動作），本實作將其表達為五角色皆 `READ`（讀取型存取允許、寫入拒）。此為對「可」的忠實編碼（普遍允許之讀取型能力），非對任何限制之簡化；附件之「浮水印下載」屬檔案存取機制（F016/F018/F020），與功能面 read 判定分離。矩陣其餘 10 列皆為 `CRUD/唯讀/無` 之直接對映，逐格與 spec 一致。

### F026 角色×欄位（權威＝F026 spec 表格）

規則：ICSOP管理員為唯一可寫（`WRITABLE`）；系統管理員／主管／部門窗口／一般使用者對所有欄位皆唯讀＝拒寫（`FORBIDDEN`）；系統產生欄位（系統 UUID）一律忽略傳入值（`IGNORE`，不論角色含 ICSOPAdmin）。

- **系統 UUID**（1 欄）：`IGNORE` × 全角色（對應 spec「唯讀（系統產生）」＋ Main Flow 3「一律忽略傳入值」）。
- **18 業務欄位**（文件狀態／制定公司／制定部門／制定室別／文件編號／當責室長-主要／當責室長-次要／文件使用部門／版次／所屬循環／所屬節點／文件連結點／ICSOP PDF／使用表單／公告日期／OJT簽到表／文件名稱／內容摘要）：ICSOPAdmin=`WRITABLE`、其餘四角色=`FORBIDDEN`。共 19 列，與 spec「共 19 欄位」一致。
- 「所屬節點」＝可寫，惟 spec 註明維護入口限 F009 節點抽屜（入口面約束，非角色權限面）→ 於欄位判定仍為 `WRITABLE`，並於程式碼註解標明。
- 「ICSOP PDF／使用表單」非 ICSOPAdmin 為「唯讀（可下載）」→ 寫入面為 `FORBIDDEN`；「可下載」屬檔案存取機制，與欄位寫入判定分離。

> 18 業務欄位於 spec 之值完全一致，實作以共用列物件 `ICSOP_WRITABLE` 表達（每格值仍為顯式、未簡化任何限制），並由 `field-matrix.spec.ts` 對全部 18 欄逐欄斷言涵蓋。

## Architectural Decisions（spec 範圍內）

1. **functionKey／fieldKey 採 spec 中文名稱字串為穩定鍵**（與任務指定之 `@RequirePermission('組織人員異動管理','write')` 一致），以常數物件 `FunctionKey`／`FieldKey` 匯出避免字串誤植。
2. **`canWriteField` 回三值**（`WRITABLE`/`FORBIDDEN`/`IGNORE`）以區分「拒寫（→ FIELD_WRITE_FORBIDDEN）」與「系統欄位忽略（不報錯）」，滿足任務「回一個可區分之結果」之要求。
3. **fail-closed**：`canPerform` 未知功能/角色 → false；`canWriteField` 未知欄位/角色 → `FORBIDDEN`。
4. **guard 鏈**：`SessionGuard`（認證，掛 `req.sessionUser`）在前、`RolePermissionGuard`（授權）在後；未標註 `@RequirePermission` 之端點本 guard 不施加限制（放行）；無 `sessionUser`／無 `roleCode` → 403 `PERMISSION_DENIED`。
5. **`RbacModule`** 提供並匯出 `RolePermissionGuard`（比照 `AuthModule` 匯出 `SessionGuard` 之重用模式），供後續各受保護模組 `imports:[AuthModule, RbacModule]` 直接使用。

## SysAdminGuard 處置

**選擇「移除」**（任務允二擇一）。`sys-admin.guard.ts` 自身 doc 註解即載明「F025 完成後應改由矩陣統一判定，並移除此類分散於各 feature 的硬編角色檢查」；F025 矩陣既已就緒，保留即為死碼。故刪除 `sys-admin.guard.ts` 與 `sys-admin.guard.spec.ts`，並改 `org-sync` 之 controller/module 引用。F004 手動同步之實際行為不變（`組織人員異動管理` 之 write 僅 SysAdmin=CRUD 通過，ICSOPAdmin 唯讀被拒、其餘無 → 與原「僅 SysAdmin」等價）。

## 待接項（後續增量，本 pass 明確不做）

- **F026 enforcement**：文件寫入端點（F010 建立／F011 編輯，尚未實作）就緒後，於 DTO/service 層以 `canWriteField` 過濾——`FORBIDDEN` 欄位被寫入 → 回 `FIELD_WRITE_FORBIDDEN`（403）；`IGNORE` 欄位（UUID）靜默忽略傳入值。屆時需建立「DTO 英文欄位 → 本 `FieldKey` 中文鍵」之對照。
