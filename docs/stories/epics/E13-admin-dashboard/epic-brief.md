## Epic Goal

後台首頁目前是一個**導覽面板**：歡迎詞 ＋ 5 張待辦計數卡 ＋ 與左側側欄逐項重複的功能卡 ＋ 最近活動流。它回答的問題是「我可以去哪裡」——而那個問題，側欄已經完整回答過一次了。⇒ 首頁的整個中段對使用者**零增量資訊**，同時佔掉了整屏最值錢的版面。

真正沒有人回答的問題是「**現在文件與訓練的整體狀況如何**」：有多少已公告、多少還沒到公告日、這個月動了哪些、教育訓練有沒有跟上、哪些單位與哪些業務類別落後。這些資料在系統裡全部都有，但目前必須逐頁點進去、逐欄自己數。

本 Epic 因此把首頁從**導覽面板**改成**狀況看板**：四張口徑明確的統計卡回答「整體數量」、兩張依組織維度切分的環圖回答「是誰在產出」、一份最新公告清單回答「最近動了什麼」、一張雙色長條圖回答「哪一類業務的文件還卡在進度中」。同時移除與側欄重複的快速進入功能區。

**本 Epic 之核心紀律（三條，違反任一條即為缺陷）**：

1. **口徑單一**——「已公告」與「進度中」在卡片、兩張環圖、長條圖共四處呈現，其判定**必須**來自同一個既有純函式 `deriveDisplayStatus`。本 repo 已多次記錄「同一件事兩個定義點，其中一處日後漏改」的缺陷形狀。
2. **數值可被文字讀到**——本輪之測試策略明示為「簡化 test-generator（只做 vitest / jest）」，**沒有視覺回歸、沒有 e2e**。圖表數值若只存在於 SVG 幾何或 canvas 中，整個功能將不可被任何自動化測試鑑別（[NFR-F044-2](../../F044-admin-dashboard-analytics.md)）。
3. **零漣漪**——側欄、`FUNCTION_MATRIX`、OJT 進度管理之完成判定與篩選項數、文件清單之欄位與篩選項數，**逐項不動**。

## Dependencies

**Depends On**：
- [E04 ICSOP 文件管理](../E04-icsop-document/epic-brief.md) — 四張卡之前三張、兩張環圖、最新公告清單之資料全部來自 `ICSOP_DOCUMENT`；已公告／進度中之判定權威為 `deriveDisplayStatus`。
- [E11 OJT 進度管理](../E11-ojt-progress/epic-brief.md) — 第四張卡之完成判定、排除規則（裁撤／孤兒）、應完成訓練日期（`公告日期 + 1 個月`）皆沿用 F042 既有定義；`查看明細` 之落點為其 TAB2。
- [E12 業務/功能類別管理](../E12-business-function-category/epic-brief.md) — 長條圖之資料來自 `BUSINESS_CATEGORY_DOC` 之 M:N 掛載；類別層去重口徑沿用 F043 `AC1`。
- [E02 組織同步](../E02-org-sync/epic-brief.md) — 環圖之組織維度（公司／本部／部門）依賴 `ORG_UNIT` 之 `tier`／`parentCode` 與 `orgUnitDisplayName`。
- [E08 權限矩陣](../E08-permission-matrix/epic-brief.md) — 各區塊之可見性一律讀 `FUNCTION_MATRIX`，**不得**另寫角色清單。

**Blocks**：
- 無。本 Epic 為首頁呈現層，不阻塞任何其他 Epic。

## Success Criteria

- 進入後台首頁即可一眼看出：已公告與進度中的文件總數、這個月公告了多少、教育訓練的完成狀況。
- 首頁不再有與側欄重複的功能卡；側欄本身**一格未動**。
- 兩張環圖可依使用者職位自動落在合適的組織維度，且使用者可自行切換；每一段與其數字**在圖例中以文字可讀**。
- 最新公告清單依公告日降冪呈現，`查看更多` 導向文件管理**且真的套用了公告日降冪排序**。
- 長條圖逐類別呈現已公告／進度中兩色，且其「掛載文件數」與類別池清單上同一列的數字**恆等**。
- 🔒 **回歸鎖定**：F025 功能矩陣逐格未動、F042 之完成判定與 TAB2 篩選項數未動、F017 之欄位與篩選項數未動，三者之既有測試全數維持綠燈**且期望值未經修改**。
